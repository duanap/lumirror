# 评分语义

## 评分维度

活动可以配置多个评分维度、允许分值范围、计入方向、比例、启用状态和取整方式。

默认综合分使用当前启用维度的真实规则计算。默认三项等权时可以理解为：

```text
综合总分 = (工作能力 + 工作态度 + 协作能力) / 3
```

如果活动配置了自定义权重或扣减项，界面和后端都应使用实际规则，而不是固定公式。

## 成员评分

成员评分的目标类型是：

```text
employee
```

## 团队整体评分

团队整体评分的目标类型是：

```text
team
```

团队结果和团队趋势必须直接来自 team 目标评分。

## 提交原子性

评分提交属于原子事务：验证任务、插入 score、插入 score values、更新任务状态、更新邀请状态和写 audit 必须一起成功或一起回滚。

同一个 task 并发提交只能成功一次，不能只依赖 JavaScript 的状态检查；数据库唯一约束必须参与保护。
